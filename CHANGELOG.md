# Changelog

## Unreleased

- (EN) New crate `ch32rv-usb-wch-win`: talks to a WCH-Link through WCH's stock Windows vendor driver (`WCHLinkW64.SYS`, CH375-family `DeviceIoControl`) from 64-bit Rust - no WinUSB replacement (Zadig) and no 32-bit-only `WCHLinkDLL.dll`, so ch32rv and WCH-LinkUtility can coexist on the same machine (ArduinoCore-CH32 request B-2, Windows). It is protocol-agnostic on purpose - device-interface enumeration by GUID, open, endpoint-addressed bulk transfers, and a parent-instance-ID helper for serial correlation - so other Rust tools can reuse it as a component. Verified live on Windows 11: a GetProbeInfo round trip on all 5 bench probes (WCH-Link CH549 fw 2.12, WCH-LinkE fw 2.22). Not yet wired into `ch32rv-usb` (the nusb-fallback integration is the next step, docs/windows-wch-driver.ja.md §4).
- (JA) 新 crate `ch32rv-usb-wch-win`: WCH 純正 Windows ドライバ(`WCHLinkW64.SYS`、CH375 系 `DeviceIoControl`)経由で WCH-Link と通信する。64bit Rust から WinUSB 置換(Zadig)も 32bit 限定の `WCHLinkDLL.dll` も不要で、ch32rv と WCH-LinkUtility が同一マシンで共存できる(ArduinoCore-CH32 依頼 B-2 の Windows 対応)。意図的に protocol 非依存 - GUID による device interface 列挙、open、endpoint 番号指定の bulk 転送、serial 突き合わせ用の親 instance ID ヘルパ - なので他の Rust 製ツールも部品として再利用できる。Windows 11 実機検証: ベンチの全 5 probe(WCH-Link CH549 fw 2.12、WCH-LinkE fw 2.22)で GetProbeInfo 1 往復に成功。`ch32rv-usb` への配線は未実施(nusb fallback 統合が次工程、docs/windows-wch-driver.ja.md §4)。

- (EN) `--capture <file>` now records the probe's USB transactions (ArduinoCore-CH32 request A-3): every bulk transfer on the WCH-Link command channel (EP 0x01/0x81) and flash-data channel (EP 0x02/0x82) is appended as one NDJSON line (`seq`, `t_us`, `chan`, `dir`, `len`, `ok`, hex `data`) behind a `_meta` header, so a protocol problem hit on the bench can be reported as a replay fixture instead of "reproduce it on hardware first". The sink lives in `ch32rv-usb` (`capture` module), is set once from `main`, and is a no-op when the flag is absent (zero cost off the flag). Verified on the bench: `target info --capture` produced 12 valid NDJSON transactions of the real GetProbeInfo / SetSpeed / AttachChip exchange.
- (JA) `--capture <file>` が probe の USB transaction を記録するようになった(ArduinoCore-CH32 依頼 A-3): WCH-Link の command channel(EP 0x01/0x81)と flash-data channel(EP 0x02/0x82)の全 bulk 転送を、`_meta` ヘッダの後に NDJSON 1 行ずつ(`seq`・`t_us`・`chan`・`dir`・`len`・`ok`・hex `data`)追記する。ベンチで踏んだ protocol 問題を「実機で再現待ち」でなく replay fixture として報告できる。sink は `ch32rv-usb` の `capture` module にあり `main` が一度設定、flag 無しなら no-op(off 時コストなし)。実機検証: `target info --capture` が実際の GetProbeInfo / SetSpeed / AttachChip のやり取りを 12 件の有効 NDJSON transaction として記録。
- (EN) `--lock-timeout` now backs a real per-probe advisory lock (docs/cli.ja.md §3.7, ArduinoCore-CH32 request A-2): before a command touches a probe it takes an exclusive OS file lock keyed by the probe serial (or the bus topology when it has no serial), so two `ch32rv` processes on the same probe serialize instead of colliding - the bench can run a monitor and an upload against one probe without them stepping on each other. It covers the attach path (`flash` / `target` / `dbg` / `write` / `monitor --source dmdata` / `capabilities` / `arduino`), the `gdb` server, and `monitor --source uart` / `sdi`, each holding the lock for the operation's duration. A process that cannot take the lock within `--lock-timeout` exits 13 (`device-busy`). The lock is an `flock`, so the OS releases a crashed holder's lock automatically (no stale-lock sweep). New `ch32rv-usb` `DeviceLock`. Verified on the bench: with one probe held by a `uart` monitor, a second command on that probe exits 13 while a command on a different probe is unaffected, and the probe is usable again once the holder releases.
- (JA) `--lock-timeout` が実際の probe 単位 advisory lock を駆動するようになった(docs/cli.ja.md §3.7、ArduinoCore-CH32 依頼 A-2): probe に触れる前に probe serial(無ければ bus topology)をキーに OS の排他ファイル lock を取り、同一 probe への 2 つの `ch32rv` プロセスを衝突でなく直列化する - ベンチが 1 台の probe に monitor と upload を並行させても踏み合わない。対象は attach 経路(`flash` / `target` / `dbg` / `write` / `monitor --source dmdata` / `capabilities` / `arduino`)、`gdb` server、`monitor --source uart` / `sdi` で、各操作の間だけ保持。`--lock-timeout` 内に取れなければ exit 13(`device-busy`)。lock は `flock` なので保持者が異常終了しても OS が自動解放(stale 掃除不要)。`ch32rv-usb` に `DeviceLock` を追加。実機検証: 1台の probe を `uart` monitor が保持した状態で、その probe への2つ目のコマンドは exit 13、別 probe は無影響、保持者が解放すれば再び使用可。

## 0.2.0 - 2026-09-02

- (EN) Initial release. `ch32rv` flashes and debugs WCH CH32 RISC-V MCUs over WCH-Link / WCH-LinkE, shipped as a CLI (`cargo install ch32rv`) and as reusable library crates. Verified on a six-board bench (CH32V003 / V103 / V203 / V307 / X035 / L103). Prebuilt binaries for Linux / macOS / Windows - Linux x86_64 is verified, the others are experimental.
- (JA) 初回リリース。`ch32rv` は WCH-Link / WCH-LinkE 経由で WCH CH32 RISC-V MCU を書き込み・デバッグするツール。CLI(`cargo install ch32rv`)と再利用可能な library crate として配布。6台ベンチ(CH32V003 / V103 / V203 / V307 / X035 / L103)で実機検証。Linux / macOS / Windows のバイナリを配布 - Linux x86_64 = verified、他は experimental。
- (EN) Release artifacts unpack into a single `ch32rv-<version>-<target>/` directory bundling the binary + LICENSE + README + CHANGELOG - arduino-cli requires the root directory, and a correctly-rooted upstream lets downstream mirrors pass the bytes through byte-identical (their provenance checksum still matches). `version --json` now reports the embedded device-DB provenance under `target_db` (`source_rev` = the `ch32-device-data` revision, plus an fnv1a64 `digest` of the embedded rows, same fingerprint convention as `flash_stub_digest`), wiring the docs/architecture.ja.md §3 reproducibility contract.
- (JA) リリース成果物は単一の `ch32rv-<version>-<target>/` ディレクトリに展開され、binary + LICENSE + README + CHANGELOG を同梱する - arduino-cli がルートディレクトリを要求し、正しく root 付きの upstream は下流 mirror がバイト同一で素通しできる(provenance checksum が一致し続ける)。`version --json` は埋め込み device DB の来歴を `target_db` で報告するようになった(`source_rev` = `ch32-device-data` の revision、加えて埋め込み行の fnv1a64 `digest`。`flash_stub_digest` と同じ指紋方式)。docs/architecture.ja.md §3 の再現性契約を配線。
- (EN) The udev rule for non-root WCH-Link access now lives in one file (`cli/60-ch32rv.rules`): `doctor --emit-udev` prints it verbatim (`include_str!`) and the Linux tarball bundles it, so the two never drift (ArduinoCore-CH32 request B-6). `uaccess` is the primary grant with a `plugdev`/`0660` fallback; it covers the WCH-Link RISC-V (8010/8011) and DAP (8012) PIDs. Tarball users install with one `sudo cp` + `udevadm reload`.
- (JA) 非 root で WCH-Link を使う udev ルールを 1 ファイル(`cli/60-ch32rv.rules`)に集約: `doctor --emit-udev` が verbatim 出力(`include_str!`)し Linux tar が同梱するので両者が乖離しない(ArduinoCore-CH32 依頼 B-6)。`uaccess` を本線に `plugdev`/`0660` を fallback、対象は WCH-Link の RISC-V(8010/8011)と DAP(8012)PID。tar 利用者は `sudo cp` + `udevadm reload` の 1 手で導入。
- (EN) flash: `flash` (program + verify) with erase modes (auto / sector / chip / none; sector is page-granular), `--restore-unwritten`, `--preverify`, `--repeat`, and a post-flash `--sdi` / `--monitor` handoff; plus `verify`, `read`, `write` (raw memory / flash), `erase` (all / range / region), and `reset`.
- (JA) flash: `flash`(program + verify)は erase モード(auto / sector / chip / none、sector は page 単位)・`--restore-unwritten`・`--preverify`・`--repeat`・書込後の `--sdi` / `--monitor` 移行に対応。ほか `verify` / `read` / `write`(raw メモリ・flash)/ `erase`(all / range / region)/ `reset`。
- (EN) debug: `dbg` halt / resume / step / regs / reg / dmi, and a gdb server with hardware and flash breakpoints.
- (JA) debug: `dbg` halt / resume / step / regs / reg / dmi と、HW / flash ブレークポイント対応の gdb server。
- (EN) target & probe: `target info` with SKU / family / debug-wiring / flash-geometry from an embedded device DB; option bytes read / decode / `set` / `write-raw` / `reset` / `protect`; `recover`; `probe list` / `info` and firmware info / check; `db list` / `info`; `capabilities`; and `monitor` (uart / sdi / dmdata).
- (JA) target・probe: 埋め込み device DB による `target info`(SKU / family / デバッグ配線 / flash 容量)、option byte の read / decode / `set` / `write-raw` / `reset` / `protect`、`recover`。`probe list` / `info` と firmware info / check、`db list` / `info`、`capabilities`、`monitor`(uart / sdi / dmdata)。
- (EN) Arduino & shell: `arduino discovery` and `arduino monitor` (the Pluggable Discovery / Monitor protocols; upload itself is plain `flash`), and `complete` for shell completions.
- (JA) Arduino・shell: `arduino discovery` / `arduino monitor`(Pluggable Discovery / Monitor プロトコル。upload は通常の `flash`)、`complete` で shell 補完。
- (EN) Library crates published to crates.io - contract, usb, dmi, target, wchlink, flash, debug - so other tools can reuse the WCH-Link protocol, the RISC-V Debug Module + FLASH-controller access, and the device DB.
- (JA) crates.io に library crate を配布 - contract / usb / dmi / target / wchlink / flash / debug - 他ツールが WCH-Link protocol・RISC-V Debug Module + FLASH controller アクセス・device DB を再利用できる。
