# 実測 device_id: CH32V006(依頼 0001 向け, 2026-09-16)

- 測定: ch32rv `target info`(WCH-LinkE 経由の AttachChip 応答 = `attach` source)
- 用途: [依頼 0001](../0001-device-id.ja.md) の `evidence/device_ids.csv` への追加データ
- 相互検証: UID は `/run/board-identify/by-id/ch32v006k8u6-f799abcd5fc7bc61` と一致

| part | family byte | chip_id (attach) | UID | flash_kb(probe) | probe serial |
|---|---|---|---|---|---|
| CH32V006 の QFN32 品 | `0x4E` | `0x00600620` | f799abcd5fc7bc61 | 62 | 497F8F06CE2F (LinkE) |

silicon revision([7:4])は `0x2`。don't-care マスク後は **`0x00600600`**。

## これが埋める穴

`evidence/device_ids.csv` の CH32V006 は **`CH32V006E8R6` の 1 行だけ**(`0x00610600`、出典 `ch32-data(673fb0f)`)。
同じ V00x でも V002 は 5 行、V005 は 4 行、V007 は 2 行あるので、**V006 だけ package 違いが欠けている**。
上流 `ch32-data` の `data/chips/CH32V006x8x6.yaml` に 1 package 分しか無いのが原因と見られる。

## 型番: CH32V006K8U6(2026-09-16 確定・収載済み)

**納品受け入れ済**: ch32-device-data@e3e723a(F-76)が `evidence/device_ids.csv` と `index/parts.csv` に収載。
暫定 overlay の行と **sku / family / series / device_id / id_addr / flash / sram すべて一致**したため受け入れ、
`crates/target/provisional/skus.csv` を空にした。`crates/target/generated/skus.csv` の同行は `verified=true`
(この実測が根拠。`xtask` の `MEASURED` に `CH32V006K8U6` を追加)。

**データシートには本当に載っていない**が、**WCH の EVT には存在する**。ch32-device-data へは連絡済みで、EVT から追加予定。

| 資料 | QFN32 62K/8K の V006 |
|---|---|
| WCH EVT | **CH32V006K8U6**(これが典拠) |
| board-identify `wch_chips.py` | `0x00600600` → **CH32V006K8U6** |
| `ch32-device-data` `catalog/products.csv` / `index/parts.csv` | **CH32V006K8U7** のみ(データシート由来なので K8U6 が無い) |
| ArduinoCore-CH32 `boards.txt` | **CH32V006K8U7** のみ |

末尾 6/7 は温度グレード(-40..85C / -40..105C)でシリコンは同一のため、**chip_id では区別できない**。
`evidence/device_ids.csv` は V007 の QFN32 品を `CH32V007K8U6`(`0x00720600`)として持っており、綴りの前例も上流にある。

残る依頼は、V006 の残り package(`0x0062` / `0x0063` 相当)の device_id も併せて収載すること。
