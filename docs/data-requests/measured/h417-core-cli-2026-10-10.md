# H417 コア選択の CLI 実装・実機検証

- 実測日: 2026-10-10
- 対象: CH32H417QEU6、chip ID `0x4170053d`、SWIO PB9。
- Probe: WCH-LinkE `49808F06CE30`、firmware 2.22、speed low。
- 根拠となる選択方式: [コア選択・CSR 読み出し実測](../0009-h417-core-selection.ja.md)。

## 実装

直接 WCH-Link 接続で `--core 1` の `dbg`（`halt --reset` を除く）と `read` に対応した。Session は attach 後に対象 family byte `0xc6` を照合し、DMI abstract command が busy でないこと、DMCONTROL の hartsel readback、DMSTATUS の unavailable / nonexistent が無いことを確認する。失敗時はレジスタやメモリ操作に進まない。

WchLink が選択を保持し、DtmAccess の借用・trait object の両経路を通じて DebugModule に渡す。DebugModule の halt / resume / reset-halt / reset-ack の DMCONTROL 書き込みは選択を保持する。raw DMCONTROL write も transport の選択記録に反映する。core 0 は従来と同じ USB 列を使い、既存 replay で確認した。

core 1 のメモリ読み出しは DMI 経由とした（probe の bulk memory read が選択を保持するかは未実測）。CLI の core 1 では Flash・option byte 変更、system reset、GDB・monitor、OEP・broker 経由を対象に含めず、未対応操作を exit 24 で拒否する。

## 実機結果

全 8 CLI 呼び出しが exit 0。JSON と USB capture を [証拠ディレクトリ](h417-core-cli-2026-10-10/) に保存した。

| 操作 | 結果 |
|---|---|
| core 1 `dbg reg read csr:0xf14` | `0x00000001` |
| core 0 `dbg reg read csr:0xf14` | `0x00000000` |
| core 1 `dbg regs` | 32 GPR と PC 読み出し成功 |
| core 1 `read --range 0x1ffff704+4` | chip ID の little-endian bytes `3d057041` |
| core 1 `dbg step 1` | `stepped=1`、PC `0x000026c0` |
| core 1 `dbg resume` | `resumed=true` |
| core 1 `dbg halt` | `halted=true`、PC `0x00000000` |
| 最後の core 1 `mhartid` 読み出し | `0x00000001` |

CLI 操作ごとの attach がすでにコアを止める場合があるため、**別途同一 attach セッション内でも resume → halt を検証した**。実装した `WchLink::select_hart` と `DebugModule` を直接使い、running DMSTATUS `0x00430c82` → halted DMSTATUS `0x004f0382` を確認。前後の mhartid は 1、最後の DMCONTROL は `0x00010001`。この capture にはコア 1 宛 haltreq `0x80010001` が実際に含まれている。

core 1 操作の host 発行 DMCONTROL は全て hartsel 1 を保持していた。Flash・option byte の書き込みや erase / reset は実施していない。step / resume は既存 firmware を実行するため、実行状態・RAM は変化する。

## 回帰検証と範囲

選択保持を halt / resume / reset-halt / ack の単体テストで確認し、CLI の識別読み出し・step・resume・halt は実機 capture の replay fixture を追加した。選択 readback が 0 に戻る合成 fixture では、core 0 のレジスタに進まず exit 24 と detach になることを確認した。合成 fixture は `tests/fixtures/replay/dbg-h417-core1-rejected.ndjson`、残る core 1 fixture は実機 capture。

今回の実測はこの chip / probe firmware に限る。他 H41x や firmware、物理 SWIO capture、選択コアの reset 制御は未検証。AttachChip / DetachChip の probe 内部動作と他コアへの影響を完全に隔離する保証は含まない。プロトコル側はこの新しい run-control 実測も根拠として収載可能。
