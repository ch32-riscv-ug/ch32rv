# CH32M030 の識別情報とデータ取得実測 (2026-10-10)

V407からM030へ入れ替えたWCH-LinkE `49808F06CE30` のSWIO経由で、CH32M030G8R7を識別した。
読み出し・書き込み保護は無効。既存FlashとOption値を保持し、書き込み・消去を行わずに取得した。
64 KiBのFlash全範囲を別セッションで再読し、byte一致を確認した。

## 識別と電子署名

| 項目 | 実測 |
|---|---|
| Probe / firmware / port | WCH-LinkE / 2.22 (v42, raw `0216`) / `/dev/ttyACM20` |
| AttachChip family / chip ID | `0x8e` / `0x03bb0810` |
| メモリ `0x1ffff384` | `10 08 bb 03` (LE32 = `0x03bb0810`) |
| silicon revision / 比較用ID | 1 / `0x03bb0800` (`0xffffff0f` mask) |
| ChipInfo容量 / UID / echo | 未取得 |
| UID `0x1ffff3a8..0x1ffff3b3` (12 byte) | `cd ab f9 04 4d bc 13 6d ff ff ff ff` |
| FLACAP `0x1ffff3a0` | `10 00` (LE16 = `0x0010`)、独立した読取でも一致 |
| Option base / raw (先頭16 byte) | `0x1ffff300` / `a55ad728ff00ff00ff00ff00ff00ff00` |
| RDPR / USER / WRP | `0xa5` / `0xd7` / `0xffffffff`、取得前後で不変 |

ローカルWCH EVT `CH32M030/EVT/EXAM/SRC/Peripheral/src/ch32m030_dbgmcu.c` の
`DBGMCU_GetCHIPID`はG8RのIDを`0x03bb0800`、番地を`0x1ffff384`と定義する。
実測はrevisionを除いて生成DBと一致。型番はIDによる識別で、刻印の目視確認はしていない。
SWIO信号はDB上PA3、2-wire使用時のクロックはPA2。

M030の電子署名・Optionは他familyの共通番地とは異なる。
ローカルWCH `CH32M030RM.PDF` 英語V1.2、§18.2は容量番地`0x1ffff3a0`、
UID番地`0x1ffff3a8/3ac/3b0`を定義する。UID末尾は消去パターン。
同資料の容量定義はKiB単位だが、実機は16 KiB相当を返す。
一方、型番DBと資料§1.2.1はFlash64 KiB / SRAM12 KiB。
**容量の不一致は未解決。64 KiBの読取成功だけで物理容量を実測確定したとは扱わない。**

## 取得範囲と検証

| 領域 | 範囲・量 | 結果 |
|---|---|---|
| Flash | `0x08000000..0x0800ffff`、64 KiB | 既存プログラムを取得。別セッションの再読とbyte一致 |
| SRAM | `0x20000000..0x20002fff`、12 KiB | raw snapshot |
| User-defined information | `0x1ffff000..0x1ffff1ff`、512 byte | 全byte `0xff`。System window内の別読取と一致 |
| System window | `0x1ffff000..0x1fffffff`、4 KiB | User information、Option128 byte、工場設定・UIDのrawを取得 |
| CPU / Debug Module | GPR x0..x31、PC、CSR35アドレス、DMI14アドレス | 読取値と通信capture |
| 周辺レジスタ | RMアドレス表由来26ブロック、323エントリ | rawとアドレス・値の対応表 |

§19.1はUser information、Option、工場設定をそれぞれ`0x1ffff000`、`0x1ffff300`、
`0x1ffff380`起点と定義する。512 byteの情報領域はBOOTプログラムではない。
原本の`boot.bin`は取得時の便宜名で、同一内容の`user-info.bin`も保存した。
RAM・レジスタは順次読取であり、単一時点の状態復元用ではない。
CSR/DMI読取の成功や0値だけでアドレスの実装有無を断定しない。


実機取得はch32rv 0.19.0 / Linux x86_64、DB源泉ch32-device-data@773f929。
詳細は原本の`version-0.json`と実行ログ。
IDは生成DBに収載済みだが、今回DBの`verified`とfamily tableは変更していない。
family byte `0x8e`は現CLI未登録で`unknown(0x8e)`警告が出る。
SKUはIDから一意に識別でき、Option取得はDB family `CH32M030`を使用する。
Flash書き込み・部分消去・loader・通信fixture等の機能試験は未実施。
