# CH32V205 / CH32X315: LinkE実機テスト (2026-10-08)

初期切り分けをWCH-LinkEで実施。UARTは未接続。Arduinoコアを使わないfixtureでCPU・Flash・Debug Module・host transportを検証した。SKU/IDのDB登録はch32-device-data@773f929を使用し、今回の結果でFlash-controller profileとRAM loader、stubのないfamilyの`run`を有効化した。

| 項目 | V205 | X315 |

Linux x86_64、ch32rv 0.18.0開発版。FixtureのGCCはxPack RISC-V GCC 14.3.0-1、`rv32ic_zicsr` / `ilp32`。DB上のID実測済み状態を維持し、暫定SKUの強制指定なしでattachした。

## 元のFlashの復元

テスト前の全Flashバックアップを保持。元の使用範囲はV205が先頭9216 byte、X315が先頭8192 byteに収まり、それより後はfamily固有の消去パターンだった。chip erase後にこのprefixを書き戻し、**全容量を再読して元のbackupとbyte単位で照合**した。X315は192 KiBを超える288 KiBも照合対象に含める。

| チップ | 退避・復元後SHA-256 (全Flash) |
|---|---|
| V205 | `07b4f8853aae36fcf4d1d63602576b7e3655628e9b1dd6205428c223e362ee06` |
| X315 | `8679960ffc3f5e93a1983861eca05ecacf5073cbd2eb3dcdef9bcaab556539f9` |

復元状態: **両方とも全Flashがbyte単位で一致、上記SHA-256も復元前後で一致**。option不変、最後のreset/PC確認もPASS。

ローカルの原本・読み戻し・JSON結果・USB captureは`target/hil-v205-x315-2026-10-08/`。各chipの`*-restore-results.json`に全容量SHA、byte照合結果、復元コマンドを記録。バックアップと大きなcaptureはgit管理外。
