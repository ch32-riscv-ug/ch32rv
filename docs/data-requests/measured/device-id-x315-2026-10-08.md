# CH32X315 の識別情報実測 (2026-10-08)

ユーザーがX315を追加したと報告した WCH-LinkE `49878F06CE37` を測定。
flash・optionの書き込みと消去は未実施。

| 項目 | 実測 |
|---|---|
| Probe / firmware / port | WCH-LinkE / 2.22 (v42) / `/dev/ttyACM3` |
| AttachChip family / ID / echo | `0xe6` / `0x31500000` / `0x31500000` |
| メモリ `0x1ffff704` | `00 00 50 31` (LE32 = `0x31500000`) |
| Silicon revision / 比較用ID | 0 / `0x31500000` (`0xffffff0f` mask) |
| ChipInfo UID | `36a0abcd9eb5bc48` |
| ChipInfo容量欄 / protection_raw | `0xe339` / `e339e339` |
| FLACAP `0x1ffff7e0` | `39 e3` (LE16 = `0xe339`) |
| `0x1ffff7e8..0x1ffff7f3` | `cd ab a0 36 48 bc b5 9e 39 e3 39 e3` |

UIDはプローブ形式の8 byte。RMのUID領域は12 byteで、今回末尾wordは消去済みパターン。
容量欄`0xe339`は消去済みパターンであり、58169 KiBという容量とは扱わない。
`protection_raw`から読み出し保護状態を推定しない。

## 根拠

WCH [CH32X315EVT.ZIP](https://www.wch.cn/downloads/CH32X315EVT_ZIP.html) の
`EVT/EXAM/SRC/Peripheral/src/ch32x3x5_dbgmcu.c`、`DBGMCU_GetCHIPID`が
次のID表と読み取り番地`0x1FFFF704`を明記する。

| 型番 | EVT ID | DB flash / SRAM | 実機ID確認 |
|---|---|---|---|
| CH32X315MCU6 | `0x315000x0` | 192 KiB / 64 KiB | 実施 |
| CH32X315CCU6 | `0x315100x1` | 192 KiB / 64 KiB | 未実施 |
| CH32X315WCU6 | `0x315200x2` | 192 KiB / 64 KiB | 未実施 |
| CH32X305RCT6 | `0x315300x3` | 192 KiB / 64 KiB | 未実施 |

MCU6はQFN76。型番はID表から解決し、刻印の目視確認はしていない。
CH32X305RCT6もデータのfamilyはCH32X315で、旧X035とは異なる。
資料由来の3行は`verified=false`、MCU6はID実機照合済みで`verified=true`。
全行、[依頼0008](../0008-ch32x315-device-id.ja.md)としてch32-device-data@773f929で納品受け入れ済み。
生成DBと暫定4行のID・番地・family・series・容量・実測状態が一致し、暫定行を削除。
全行`provisional=false`へ移行し、MCU6の`verified=true`を維持した。

[CH32X315DS0.PDF](https://www.wch.cn/downloads/CH32X315DS0_PDF.html) 英語V1.2、PDF p.3は
Flash総量480 KiB、うちゼロウェイト領域192 KiB、その他288 KiB、SRAM64 KiBと明記する。
ch32-device-data `index/parts.csv` の `flash_bytes=196608` はゼロウェイト領域の容量。
`index/flash_geometry.csv`もこの区別を注記している。ch32rvは既存DB契約どおり192 KiBを使う。
総量480 KiBを検証済みの読み書き範囲として自動的に広げない。

[CH32X315RM.PDF](https://www.wch-ic.com/downloads/CH32X315RM_PDF.html) 英語V1.2、PDF p.344と
`index/esig.csv`で電子署名アドレスを照合。
debug配線PA13/PA14 (1-or-2-wire)、flash geometry・option layoutは生成DBに収載済み。
Flash書き込みの実機検証は未実施。


容量欄が0/`0xffff`/`0xe339`の場合、共通Sessionは容量として使わず、一意に解決したSKUの
DB容量へフォールバックする。DB未登録なら容量は未取得とする。JSONは生値と出所を残す。
この容量選択は識別表示・flash範囲判定・領域読取・debugの範囲判定に共通で使う。
