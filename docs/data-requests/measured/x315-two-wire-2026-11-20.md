# CH32X315 の 1 線と 2 線の切り替え (2026-11-20)

WCH-LinkE(`FBC18F0680B0`、fw 2.23)→ CH32X315MCU6(UID `36a0abcd9eb5bc48`)。線は OEP の ESP32-P4X(`e8f60ae84dd7`)で
LinkE の側のピンから取った。生の記録と手順は wireskein-captures の `x315-linke-2026-11-20/two-wire/README.ja.md`。

## 分かったこと

- **X315 を 2 線にする**: 1 線で DMI `0x7E`(config_pre)← `0x5AA50401`、続けて `0x7D`(config)← `0x5AA58403`。この後は
  RVSWD(SWDIO = PA13、SWCLK = PA14)で答える。**1 線へ戻す**: `0x7E` ← `0x5AA58401`、`0x7D` ← `0x5AA58403`。config_pre の
  bit 15 が 0 で 2 線、1 で 1 線(QingKe のマニュアルの表と逆)。[V407 の実験](oep-m030-v407-2026-10-22.md)は config に
  `0x5AA58000` を書いていて、2 線に入れなかった。
- **保存されない**: オプションバイトは前後で同じ。X315 は電源を入れると 1 線で起きる。システムリセット / NRST の後に残るかは未確定。
- **WCH-LinkE**: WCH-LinkUtility の「2 線」のプルダウンは `81 0d 02 ee 03`(1 線は `ee 02`、応答 `82 0d 01 00`。`ee 00` / `ee 01`
  は SDI print)。LinkE の RAM のモードで、USB のセッションをまたいで残り、LinkE の電源を切ると消える。2 線のモードの LinkE は
  接続のたびに、1 線で上の書き込みをしてから 2 線で続ける。1 線のモードの LinkE は、接続の頭に 2 線で「1 線へ戻す」書き込みを出す。
- **ch32rv(0.32.3)への影響**: ch32rv は `ee 02` / `ee 03` を送らない。LinkE が `ee 03` のままだと `target info` は
  `target-no-response`(各セッションの最初の接続が失敗する)。X315 が 2 線のまま LinkE を `ee 02` に戻すと、電源を入れ直すまで
  接続できなかった。
- **速さ**: LinkE の速さ high で、2 線の SWCLK は約 472 kHz、DMI のフレームの間隔は 1 線の約 46 µs に対して約 125 µs。2 線の
  速さは別の命令(`81 0c 02 …`、WCH の DLL の `SetTwolineLowSpeed`)で決まるらしく、今回は送っていない。

## 未確定(X315 を OEP の治具に移してから測る)

OEP での切り替え、リセット後に 2 線が残るか、2 線を速くしたときの速さ、target のクロックを落としたときの 1 線 / 2 線、1 線のときに
PA14 を GPIO に使えるか、CPU から SDI の config を書けるか(コアの起動時に設定するかの判断材料)。ch32rv の `--wire 2`
(LinkE に `ee 02` / `ee 03` を毎回明示して送り、接続を 1 回やり直す)は、その結果を見て入れる。
